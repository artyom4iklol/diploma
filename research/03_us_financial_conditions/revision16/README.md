## Что читать

`Note_for_supervisor.docx` — основная записка от лица студента, обычное оформление. Тот же текст — `RESPONSE_TO_SUPERVISOR.md`.

`INTERNATIONAL_MECHANISM.md` раскрывает международные каналы и границы их проверки. `LITERATURE_AND_CONTRIBUTION.md` сопоставляет близкие исследования, формулирует умеренную новизну и план трёх глав. `CALENDAR_AUDIT.md` объясняет каждое правило доступности и отдельную проверку версий NFCI.

## Что рассчитано

Основные 2460 прогнозов этапа 15 сохранены без изменения. Итоговые таблицы пяти моделей содержат отношения потерь к BASE, HIST и AR, оба горизонта и все четыре спецификации. Добавлены все поочерёдные исключения одной даты из оценки, переобучение без целевых интервалов 2020–2021 годов (615 прогнозов), описательные интервалы для короткого периода 2022–2025 и частичная винтажная проверка NFCI (113 прогнозов).

Для 64 дат прогноза проверены фактические регулярные выпуски ВВП предыдущего квартала, для ESI — 128 фактических дат двух используемых месяцев. Составлен календарь 10 431 пары обучения. Проверка изменения текущего и будущего ВВП не меняет прогнозы в 24 контрольных случаях.

Получены все 59 версий NFCI на конец квартала 2011Q2–2025Q4 из ALFRED. На каждой дате заново агрегируется вся история NFCI на доступной тогда версии. Остальные переменные пересмотренные. Начало публикации NFCI — 13 апреля 2011 года; первые пять дат основной проверки не являются осуществимыми историческими прогнозами с этим индексом.

## Воспроизведение без сети

Из корня проекта, после установки зависимостей из `revision16/requirements.txt`:

1. `python final_check/run.py` — прежний основной расчёт, если нужно повторить его с нуля.
2. `python revision16/analyze_models.py` — общие сравнения и новые проверки обучения/подпериодов.
3. `python revision16/nfci_vintage_audit.py` — частичная винтажная проверка по включённым CSV, без загрузки из сети.
4. `python revision16/publication_start_sensitivity.py` — описание оценок после начала публикаций.
5. `python revision16/audit_calendar.py` — календарь по включённым источникам.
6. `python revision16/check_unreleased_gdp.py` — контроль текущего и будущего ВВП.

Шаг 1 уже выполнен на этапе 15; для остальных достаточно приложенных `final_check/results`. Загрузка дополнительных источников вынесена в отдельные скрипты. `nfci_vintage_audit.py --download` использует сеть только для отсутствующих файлов, в текущем архиве все CSV уже есть. Порядок и seed блочной перевыборки записаны в коде. Числа могут незначительно отличаться на другой версии оптимизатора при неединственном решении квантильной регрессии.

## Файлы результатов

- `central_comparison.csv`: все модели, четыре варианта, оба горизонта, отношения к BASE/HIST/AR.
- `subperiod_comparison.csv`: все модели по исходным эпизодам, без выбора только победителей.
- `single_origin_influence.csv`, `leave_one_out_best_model.csv`: влияние каждой прогнозной даты.
- `no_covid_training_forecasts.csv`, `no_covid_training_scores.csv`: переобучение после исключения обучающих целевых интервалов, затрагивающих 2020Q1–2021Q4; даты оценки сохранены.
- `recent_subperiod_descriptive_intervals.csv`: фиксированные потери, круговые блоки 4/8, 5000 повторений, seed 15102026; это не формальный тест превосходства.
- `nfci_partial_vintage_forecasts.csv`, `nfci_partial_vintage_scores.csv`, `nfci_partial_vintage_features.csv`: только NFCI заменён историческими версиями.
- `forecast_calendar_all_origins.csv`, `esi_monthly_release_audit.csv`, `training_pair_calendar.csv`: полный календарь.
- `*_validation.json`, `unreleased_gdp_mutation.json`: результаты проверок и ограничения.

## Научный вывод

Допустима сравнительная ретроспективная работа с умеренной прикладной новизной. NFCI улучшает BASE на h=1, но в основной схеме уступает HIST. Значительная часть выигрыша связана с 2020Q4 и экстраполяцией лагового роста. Проверка на исторических версиях NFCI ослабляет выигрыш. Устойчивое превосходство в реальном времени и причинная передача не установлены.

Пять замечаний рассмотрены, но полнота календаря не означает полноты исторических числовых версий: GDP EA20, ESI и New CISS остаются ограничениями. Если руководитель требует строгий real-time для всех рядов, текущий дизайн этому требованию не соответствует. Такое ограничение нельзя удалить изменением формулировки или дополнительным подбором спецификаций.
